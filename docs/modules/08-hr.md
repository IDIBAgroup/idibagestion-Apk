## 2. Current state

- Local collections: `employees`, `contracts`, `candidates`, `leaves`, `performanceReviews`, `feedback360`, `personalDevelopmentPlans`, `activityReports`.
- `DepartmentsPage` (module 01) is also read here.

## 3. Target data model

- To add: `employees` (linked to `users` optionally), `employment_contracts`, `leave_types`, `leave_requests` + balances, `candidates` + `interviews`, `performance_reviews`, `activity_reports`.

## 4. API (tRPC)

- `employee.*` (with field-level visibility)
- `leave.request/approve/reject/balance`
- `recruitment.*`
- `review.*`
- `activityReport.*`

## 5. Implementation steps

1. [ ] Employees first (other HR pages depend on it), keep salary fields out of this module (module 09).
2. [ ] Leave requests with manager approval and balance calculation on the server.
3. [ ] Recruitment pipeline (candidates, stages).
4. [ ] Performance reviews and activity reports.
5. [ ] Population-based access: employee sees own data, manager sees direct reports, HR sees all.
6. [ ] Notifications for leave requests/approvals.

## 6. Depends on

- [ ] Leave balance matches approved requests.
